#  Magic Market

**Magic Market** is a 2D top-down farming and shop management simulation game developed with Unity and C#.

The game combines two different gameplay experiences into one cycle: managing a shop during the day and taking care of a magical farm at night. Players manage their inventory, interact with customers, grow crops, and develop their business.

##  Game Overview

Magic Market features a day-and-night gameplay loop where players switch between shop management and farming activities.

- **Daytime:** Run your own market, organize products, manage inventory, and sell goods to customers.
- **Nighttime:** Enter a magical garden, plant seeds, grow crops, and prepare products for the next business day.
- **Resource Management:** Manage energy, inventory, crops, and shop resources.
- **Business Management:** Set product prices and manage the shop's economy.

##  Technical Features & Systems

The project includes several gameplay systems and software architecture concepts developed using Unity and C#.

### Gameplay Systems

- **Day-Night Cycle:** A gameplay loop that transitions between daytime shop management and nighttime farming activities.
- **Inventory System:** Manages item storage, item data, and inventory interactions.
- **Market System:** Handles shop management, product sales, customer interactions, and product pricing.
- **Character Controller:** Handles player movement and character controls.
- **Energy System:** Manages player energy and resource consumption.
- **Crop & Farming System:** Supports seed planting, crop growth, and farming interactions.
- **Trigger-Based Interactions:** Uses Unity Collider and Trigger events to detect interactions between the player and gameplay objects.

### Software Architecture & Design Patterns

- **MVP (Model-View-Presenter):** Separates data, presentation, and application logic to improve code organization and maintainability.
- **Singleton Pattern:** Provides centralized access to managers and shared gameplay systems.
- **ScriptableObjects:** Used for data-driven item definitions and reusable game data.
- **Event-Driven Architecture:** Uses events and delegates to communicate between gameplay systems and reduce direct dependencies.
- **Object-Oriented Programming:** Applies encapsulation, inheritance, abstraction, and modular code organization where appropriate.
